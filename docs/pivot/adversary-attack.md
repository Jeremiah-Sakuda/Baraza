## CONCEPT 1: THEORY-OF-USER

**1. THE KILL ATTEMPT.** The concept's central claim to a judge is falsifiable and, as written, false: *"A judge can replay the fold and get the same behavior."* The fold is deterministic; the Gemini call it feeds is not. Replaying the fold reproduces the **policy prompt**, not the behavior. The moment a hostile judge asks "run it twice," the flagship word — *deterministic adaptation* — collapses into "deterministic prompt assembly," and the follow-on line writes itself: *"So this is a settings page with a subpoena metaphor."* The second barrel: there is no work being adapted. The task executor is admitted-unbuilt and undefined; the demo task is the agent drafting docs about itself. An agent whose only demonstrated job is writing, adapting only how it writes, holding beliefs like "stop hedging in my emails," is — in the adversary's exact prior words — a preference list dressed up, now with excellent paperwork. The trust-layer company thesis is real, but the demo instantiates it on the thinnest possible substrate.

**2. THE FAKE-ADAPTATION TEST.** Strip the ceremony and the mechanism is: extract preferences from user turns → user approves → fold assembles them → **stuff them into the system prompt with citation comments**. That is prompt-stuffed preference memory — the exact thing §4 claims every other entry will have. What's genuinely not a costume: the due-process layer (append-only, contradiction detection *on the user's own guidance*, retraction that provably changes the next run, no belief acts unapproved). No heuristic hides in that; it's inspectable machinery and nobody else will have it. But the *adaptation* layer survives hostile inspection only if extracted beliefs have conditional/judgment shape ("cite-first unless recipient is internal") and at least one belief changes something other than prose style — e.g., a refusal or a routing decision. The concept knows this (its own depth-of-model risk) but the extraction prompt that would deliver it is unwritten. Verified worse: the two evidence artifacts for phrase 6 are misrepresented as reuse — `differential.py` diffs ledgers, not outputs (the "behavioral diff" is a new module wearing an old filename), and `adaptation_metric.py` measures the deleted heuristic (the "generalization" is a new metric). Phrase 6's proof surface is ~100% net-new.

**3. THE DEMO-COLLAPSE TEST.** Six beats (proactive push, live claim panel, Firestore rejection, contradiction litigation, dossier reject-rerun, behavioral diff) in 4 minutes, every one requiring a web UI of which zero lines exist. The concept's tell is its own sentence: the UI is "most screen time, least code" — the demo's face is entirely unbuilt. Beat-by-beat: Firestore rejection on camera — real, already proven, stageable. Contradiction firing on a belief committed in a prior logged session — real machinery (`reconcile/detect.py` on-write path exists), stageable without fakery if the plant is seeded in genuinely prior state. Reject-and-rerun with changed behavior — stageable and strong. The collapse points: (a) the annotated causal diff — "this diff line caused by claim c-041" is not something any existing machinery can honestly assert; under the no-fabrication rule the honest version is "here is the prompt delta with citation, here are the two outputs," which is visibly weaker than the storyboard; (b) cold start — the chat-export seeding path requires a new extraction prompt (verified: current extractor targets registered document chunks) and if it underdelivers, minute one is an empty dossier; (c) "leads the way" is a cron push behind a trigger that currently 403s — even fixed, it's the weakest initiation story in the set and reproduces the panel's original finding.

**4. THE SCOPE TEST.** The invisible 70% genuinely carries: claim/anchor/quote_for, append-only rules, fold, model-free approver, on-write detect, session store — all verified present and matching the concept's descriptions. But the demo-visible surface is ~100% new: doctrine compiler (new), task executor (new and undefined — the biggest unscoped item), web UI (new, demo-critical), initiator + 403 fix (new), turn-level preference extraction (new prompt + path), behavioral diff (rewrite), metric (rewrite), plus the still-empty `fixtures/transcripts/`. "70% of the test surface carries" is true and irrelevant to category C: judges score the 30% that doesn't.

**5. VERDICT: survives-with-amputations.** Amputate: (1) the "replay the fold, same behavior" claim — restate as "same policy, every rule cited," or a judge kills it live; (2) the causally-annotated output diff — replace with prompt-delta-plus-output-pair, honestly framed; (3) Scheduler-push as the leads-the-way story. Keep the organs nobody else has: dossier view, reject-rerun, contradiction-on-the-user, approval-gated beliefs.

**5.
